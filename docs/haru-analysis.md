# Haru-4B 원인 분석과 검증 — 2026-11-18

## 공식 구성

[Haru-4B 모델 카드](https://huggingface.co/higurashi-ai/Haru-4B)와 [공식 MLX 코드](https://github.com/higurashi-ai/Haru)는 입력 음성과 모델 음성·텍스트를 약 133ms 단위로 함께 처리하는 전이중 모델을 설명한다. 기본 목소리는 포함하지 않으며, 권리를 가진 한 화자의 깨끗한 참조 음성이 필요하다. 공식 공개 예시에는 일본어·영어가 사용되었고, 한국어는 중점 지원 언어 중 하나이지만 공식 자료가 다른 언어와 동등한 품질을 보장하지는 않는다. [공식 데모](https://www.higurashi.ai/haru4b/), [기술 블로그](https://blog.higurashi.ai/melte/haru4b/).

모델은 지시를 정확히 따르는 완성된 어시스턴트가 아니라 연구용 사전학습 모델이다. 침묵·숨소리·웃음·맞장구는 모델 출력에 포함될 수 있으므로 이를 일괄 제거하지 않았다. 모델이 낸 텍스트는 상대의 음성을 독립적으로 전사한 결과가 아니다.

## 기존 결과와 가능한 원인

과거 Discord 연결도 공식 MLX native 서버를 사용했다. 다만 int8 양자화, CPU 예열 0ms, 사용자 정의 한국어 카드와 참조 음성을 썼으므로 공식 예시와 완전히 같은 설정은 아니었다. 당시 숨소리 사례에는 입력 레벨·모델 텍스트·재생 부족이 기록되지 않아 **정확한 원인은 확정할 수 없다**. 추가로 소켓 입력이 드물게 유실돼도 기존 상태 표시가 이를 포함하지 않는 문제를 발견했다. 과거 그 통화에서 실제 유실됐는지는 확인할 수 없다.

4.66초 KSS 참조와 동일한 50초 한국어 합성 입력, seed 0, int8 모델로 이번에 원본 모델을 Discord 없이 직접 재실행했다. 모델의 출력 텍스트에는 질문자의 이름을 자신의 이름처럼 말하거나 관계없는 내용이 포함됐다. 공식 한국어 카드로 바꾼 대조에서도 질문과 무관하거나 자기소개를 반복하는 내용이 나왔다. 각각 단일 시험이며 음성 청취·다른 질문·실제 사람의 마이크를 대신하지 않는다. 결과는 `artifacts/haru-recheck-20261118/`, `artifacts/haru-official-card-20261118/`에 있다. 출력 텍스트는 별도 ASR이 아니다.

같은 Mac의 이전 비교에서 동일 50초 합성 입력에 대한 모델 프레임 p95는 int8 86.8ms, BF16 129.1ms였으며 프레임 예산은 133.3ms다. BF16도 실행됐지만 오답이 남았다. 이번 int8 직접 실행 p95는 92.0ms, 공식 카드 대조는 92.2ms였다. MLX peak는 실험별 측정이며 전체 프로세스 또는 Discord 통화 지연이 아니다. **양자화나 참조 음성만을 문제 원인으로 결론 내릴 수 없다.** 이어서 같은 Mac에서 BF16으로 실제 20ms 입력·Opus 경로를 돌린 재시험은 입력 대기가 0.5초 한도를 넘어 중단됐다. 실시간 부하에서는 이 구성이 안정적으로 동작하지 않았으므로 기본값은 int8로 정했다.

## 이번 수정과 검증

- 공식 `haru_mlx.native` 서버, 동일 프레임 형식·기본 guidance 1.5를 사용하고, native 기본 30ms 스케줄러 예열을 복원했다.
- int8과 BF16을 설정으로 고르고, 사용자 요청에 맞게 10분 앱 타이머 기본값을 비활성화했다. 원본 모델의 27,000프레임 제한은 약 60분이다.
- 입력·무음을 중단하지 않고 출력과 동시에 처리한다. 입력·출력 유실은 숨기지 않고 종료 이유와 함께 기록한다. 단계시간과 입출력 RMS, 재생 부족도 표시한다. 세션 경로의 첫 시험은 모델 p95 약 80ms인데도 20ms `setInterval`의 누적 오차로 6초 만에 입력 버퍼가 넘쳤다. 단조 시계 기준으로 최대 4프레임까지 따라잡도록 고친 뒤 재시험에서 입력 676패킷, 모델 102/102프레임, 입력·출력 유실 0을 확인했다. 측정 구간 재생 대기 11회(각 20ms), 프레임 p95 78.9ms. 모델 텍스트는 수도 질문에 관련 없는 말이었으므로 대화 성공이 아니다. 결과 `artifacts/session-bridge-2026-11-17T23-54-44-154Z/`.
- 이전 STT→LLM→TTS·검색·Animalese 실행 코드를 정리했다. 사용자 호출어와 인터넷 검색은 원본 모델에 별도로 구현돼 있지 않으므로 함께 제거됐다.
- 실모델 소켓과 Opus 왕복 합성 시험에서 입력 870패킷, 모델 출력 131/131프레임, 입력 소켓 유실 0바이트, 출력 유실 0프레임을 확인했다. 모델 처리 p95는 80.0ms였다. 이 시험의 모델 출력은 인사와 자기소개에 그쳐 답변 품질의 성공을 뜻하지 않는다. `artifacts/bridge-2026-11-17T23-47-30-565Z/`.

자동 검사는 Discord 서버와 DAVE 네트워크, 여러 사용자의 실제 마이크, 청취, 겹쳐 말하기 또는 대화 정확도를 검증하지 않는다. 사용자의 실통화에서 이 항목들을 확인해야 한다. 이전 소스의 미커밋 변경은 `.runtime/backups/`에 보존했고, 기존 모델·음성·로그는 삭제하지 않았다.
