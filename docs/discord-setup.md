# Discord 전이중 음성 연결

다른 기기의 마이크 → Discord → Mac의 봇 → 공식 Haru-4B MLX 모델 → Discord → 참가자의 스피커로 연결합니다. Mac의 마이크나 공개 웹 서버는 필요하지 않습니다. Mac과 Discord 연결이 계속 켜져 있어야 합니다.

## 설정

Discord Developer Portal에서 봇을 만들고 서버에 초대한 뒤 `.env.example`을 참고해 로컬 `.env`를 설정합니다. 토큰은 채팅이나 Git에 올리지 마세요. 음성에는 **채널 보기, 연결, 말하기** 권한이 필요합니다. 설정한 서버의 모든 멤버가 `/haru` 명령을 사용할 수 있습니다. `join`과 `reset`은 요청한 멤버가 접속한 음성 채널에서 실행됩니다.

### 호출어 채팅 (Gemma)

등록된 채팅에서 하루를 부르면 현재 연결된 통화에서 유나 목소리로 답합니다. 먼저 음성 채널에서 `/haru join`을 실행하세요. 마이크와 채팅으로 같은 대화를 이어갈 수 있습니다.

- `/haru chat add`에서 하루가 볼 채널을 한 번에 최대 25개 선택합니다. 하루는 해당 채팅 채널을 볼 수 있어야 합니다. 일반·공지 채널에서는 작성자가 통화방을 보고 입장할 권한이 있어야 합니다. 음성 채널 안의 채팅은 하루가 해당 통화방에 연결됐을 때 사용할 수 있습니다.
- `/haru chat list`로 본인이 볼 수 있는 등록 채널을 조회합니다. `/haru chat remove`에서 선택한 채널만 해제합니다. 등록 목록은 Mac의 `.runtime/chat-channels.json`에 저장됩니다.
- 등록한 채널에 `하루야, 7 더하기 5는 얼마야?`처럼 작성합니다. 일반 메시지의 호출어를 받으려면 Developer Portal의 Bot 설정에서 **Message Content Intent**를 켭니다. 꺼진 상태에서는 `@하루 하루야, 안녕!`처럼 봇을 직접 멘션하고 부를 수 있습니다.

- `HARU_LANGUAGE`: `ko` 또는 `ja`.
- `HARU_REFERENCE_PATH`: 사용 권리가 있는 3초~3분 단일 화자의 깨끗한 음성. 비우면 해당 언어의 로컬 기본 참조를 사용합니다.
- `HARU_QUANTIZE`: 운영 기본값 `8`은 언어 모델 백본을 양자화합니다. 연구 비교용 원본 정밀도는 `bf16` 또는 `none`입니다. 음성 코덱과 생성 헤드는 원본 정밀도를 유지합니다.
- `HARU_MAX_SESSION_SECONDS`: `0`이면 앱 타이머 비활성화, 그 외 60~3600초. 모델 자체는 기본 약 60분 한도가 있습니다.

```bash
./scripts/haru setup
./scripts/haru download
./scripts/haru bot-setup
./scripts/haru bot-doctor
./scripts/haru bot-invite
./scripts/haru bot-register
./scripts/haru bot
```

기존 서버에서 사용 중이면 초대·명령 등록을 반복할 필요가 없습니다. `caffeinate -i ./scripts/haru bot`으로 실행 중 유휴 절전을 막을 수 있습니다.

## 사용과 진단

1. 봇의 `Haru-4B MLX model ready` 로그가 나올 때까지 기다립니다.
2. 서버의 일반 음성 채널에서 `/haru join`을 실행합니다. 모델은 지속적으로 음성을 받아들이며 호출어를 강제하지 않습니다.
3. `/haru status`로 수신 패킷, 프레임, 입력·출력 버퍼, 소켓 입력 유실, 최근 모델 처리 p50/p95와 재생 부족을 확인합니다.
4. `/haru reset`은 모델 문맥을 초기화하고, `/haru leave`는 음성 채널을 나갑니다.

음성 출력 중에도 입력은 유지됩니다. 사용자가 동시에 말하면 한 스트림으로 섞이므로 발화자 개별 식별은 보장하지 않습니다. 이전 STT 파이프라인의 검색·호출어 제한은 사용하지 않습니다. 한국어 입력의 별도 전사도 제공하지 않습니다. 모델이 생성한 텍스트·오류·연결 종료 사유만 `.runtime/voice-debug.jsonl`에 기록하며 원본 음성은 저장하지 않습니다. 로그는 로컬의 민감한 데이터이므로 참가자에게 알리고 공유에 주의하세요.

버퍼가 넘치면 음성이 누락된 채 계속 진행하지 않도록 연결을 종료하고 사유를 남깁니다. 지속적으로 재생이 부족하거나 프레임 p95가 약 133ms보다 높으면 GPU 부하나 `HARU_QUANTIZE` 설정을 확인하세요. 일시적 Discord 연결 중단은 복구를 시도하고, 실패하면 다시 `/haru join`합니다.

참조 음성은 발음·음색에 영향을 줄 수 있지만 답변의 정확도를 보장하지 않습니다. 숨소리나 침묵만 나온다면 입력 RMS, 모델 텍스트, 모델 프레임 시간, 유실량과 재생 부족을 함께 확인하고, 같은 질문·참조로 [분석 기록](haru-analysis.md)의 로컬 비교와 대조합니다.
